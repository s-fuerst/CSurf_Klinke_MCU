* [6/13] v0.9.5 Release
** DONE Track/Mixer mode (PanMode): show fader value on touch with meters-on-display
   While a fader is touched, keep the value it controls (Volume, or Pan in
   flip mode) visible on row 1, even when "meters on display"
   (UNIT_FLAG_METERS_ON_DISPLAY) is active and would otherwise cover it with
   the level-meter bar.
   Scope (confirmed):
   - Non-ProX units only. ProX units show every value on their 4 rows anyway.
   - On extender units this only makes a difference when meters-on-display is
     ON; with it off the fader-controlled value is already visible in row 1.
   - Implemented by suppressing the LCD meter bar for the touched channel
     (MultiTrackMode::suppressDisplayMeterForValue + MeterBridge); the value
     text is already written every frame by PanMode::updateDisplay.
   Mode assignment: Track/Mixer (PanMode). Fader-controlled value.
** DONE Pan-Mode VPOT motion: briefly show the VPOT value
   For ~1 second after a VPOT is turned, row 1 shows the value the VPOT
   controls (Pan, or Volume in flip mode) instead of the fader-controlled
   value, then reverts.
   Scope (confirmed):
   - Pan-Mode only (the mixer/track mode). NOT Action/Command mode: turning a
     VPOT there triggers a Reaper action, so there is no meaningful value to
     show.
   - Non-ProX units only. The VPOT-controlled value is otherwise not visible
     on a single-panel unit (row 1 shows the fader's value), so this applies
     regardless of meters-on-display (and also suppresses the LCD meter bar
     during the window).
   - Implemented via PanMode (VPOT_VALUE_SHOW_MS window, updateDisplay swap,
     suppressDisplayMeterForValue override).
** DONE Optimize DisplayHandler::sendDifferences()
   Re-introduce diffing against m_pHardwareState: only send the changed
   runs, each still chunked (CHUNK=4) to stay under the JACK/MIDI SysEx
   fragmentation threshold. Implemented 2026-07-21: sendDifferences() now
   diffs the logical row against m_pHardwareState (read at the HARDWARE row
   index to mirror switchRows(), which sendToHardware applies before writing
   the state), finds maximal changed runs, and sends each run in 4-byte
   SysEx chunks. A one-field value change costs one short run, not the whole
   row. Correctness anchors preserved: 0x01 invalid-text init (forces first
   paint), the memset in switchTo(), and sendToHardware updating
   m_pHardwareState for every byte emitted (keeps the diff accurate, incl.
   after the Schaltmix-handoff blanking in csurf_mcu.cpp). The stale
   'whole-row' comment in csurf_mcu.cpp was rewritten; see ai-docs
   Linux-Port-Changes.md 4.2.
